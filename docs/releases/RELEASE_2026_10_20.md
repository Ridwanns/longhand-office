# Research, performance and continuity update

This implements the first usable release across the five approved directions. `AUDIT_RECOMMENDATIONS_2026_10_20.md` retains the earlier assessment against source `2c962be`; the following describes the resulting implementation.

## Available in the frontend

- **Model accountability** is a dedicated Research Lab view. It recomputes RMSE, MAE, direction and observed interval coverage from frozen registrations and retained outcome prices. Cohorts separate market, currency, price basis, horizon and recorded core version. Baselines use identical outcomes; pending, withheld, overlapping and limited samples stay visible. Legacy registrations without core version are labelled unrecorded. Advanced models retain their existing historical diagnostics and are not claimed to have prospective validation.
- **Portfolio performance** retains a sourced workbook with complete start/end NAVs, external cash flows, before/after flow NAVs and exact-date direct FX rates. TWR geometrically links subperiod returns. MWR solves conventional dated investor cash flows with ACT/365 XIRR; nonconventional flows withhold a result rather than selecting an arbitrary root. Missing inputs withhold the affected metric. The FX bridge shows native return, currency movement, interaction and residual. Editing the ledger marks the retained workbook stale. Fee/dividend effects belong in NAV and are not counted again as external contributions.
- **Synchronized quarterly regime** selects the latest completed common GDP quarter and the CPI YoY rate in each quarter's final month. Current/prior rates inside each metric must use the same source series. No interpolation, quarterly-average substitution, annual-to-quarter conversion or nowcast is performed. Missing or older common quarters are explicitly identified. It recomputes from the existing scheduled publication pipeline; provider failures and manually reviewed sources retain their dates.
- **Workspace backups** now include retained Data Sources datasets and source studies, alongside records, models, drafts, preferences and forecasts. Old backups remain supported. Restores validate source hashes/studies and open a separate workspace.
- **UI changes** add consistent evidence cards, responsive input forms, clearer valuation-sensitivity labels and a separate accountability destination. Nonfunctional Treasury/Governance placeholder cards are removed. Existing routes and stored records retain their identity. Both quadrant axes now share a common scale; the zero-to-point vector is explicitly distinguished from a historical path. A delayed Macro redraw can no longer rewrite a newer navigation route.

## Private sync activation

GitHub Pages remains the public frontend. The optional client and separately operated checkpoint service are implemented and tested locally, including two browser contexts, ciphertext-only storage, authentication, conflict rejection, immutable history and isolated recovery. **No private service has been provisioned or deployed.** Until one exists, use password-protected file backups across devices. Setup and operating boundaries are in `PRIVATE_VAULT.md`.

The service provides encrypted checkpoints, not automatic financial-record merging, certified forecast timestamps, an organization identity system, or real-time collaboration. Active device records remain unencrypted. Do not interpret local tests as an independent security assessment.

## Verification and limits

The release is checked with Node unit tests, isolated API tests, independent Decimal/calendar arithmetic checks over published public inputs, source-data recovery tests and browser checks at desktop/mobile sizes. Test portfolio data and vault credentials are confined to disposable contexts and temporary/in-memory databases. No owner browser profile or real private records are used for these tests.

Independent finance checks cover arithmetic and supplied coverage, not the truth of every provider statement or future predictive accuracy. A successfully validated input contract is not proof that a provider value is economically correct. Unavailable series, rejected SEC acquisitions and source lags remain visible; the release does not fabricate replacements or claim complete global data coverage.

Method reference: [GIPS Standards Handbook, input data and calculation methodology](https://www.gipsstandards.org/standards/gips-standards-for-firms/gips-standards-handbook-for-firms/). This implementation makes no GIPS compliance claim.
