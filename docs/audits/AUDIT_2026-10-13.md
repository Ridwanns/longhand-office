## Verified defects and fixes

| Defect and reproducible trigger | Corrected behavior | Evidence |
| --- | --- | --- |
| A historical valuation before the first purchase crashed when an earlier deposit tagged that same recorded instrument. | Historical events retain the original instrument reference universe while including only accounting events through the assessment date. | Historical cash-flow regression. |
| An extra `type: Deposit` field on a purchase could reclassify the trade as a cash flow. | Ledger event kind comes from its source collection, overriding unrelated input fields. Purchase cost, quantity and cash remain correct. | Opening 1,000, purchase 1 at 100: cash 900, quantity 1, cost 100. |
| Filtering legacy events for a historical date could change implicit same-day ordering relative to explicit sequences. | Original indexes are assigned before filtering, preserving the recorded sequence. | Mixed implicit/explicit historical ordering regression. |
| A malformed ticker pattern was ignored by modern browser validation. | Valid US share classes and IDX suffixes have valid market-specific patterns; malformed input is rejected before a new tab opens. | `BAD!` and wrong IDX length reject; `BRK.B` and `BBCA.JK` pass. |
| Tabs open across a server restart retained an expired write token indefinitely. | Only an explicit pre-write `LOCAL_TOKEN_EXPIRED` rejection refreshes the token and retries once. Foreign-origin, network and ambiguous-commit failures never replay writes. | Live browser expiry check, API security checks, storage-client tests. |
| A delayed older vault read could overwrite newer records/revision in the client. | Validated responses retain the latest revision and cached data; older responses cannot regress state. Request payloads are captured before waiting for token acquisition. | Out-of-order revision 2/3 and payload-capture tests. |
| A peer-tab update could remove a committing form, then its save callback dereferenced removed DOM. | Committing forms stay mounted; stale saves show the revision-conflict error without overwriting peer records or throwing. | Delayed real POST plus peer save and BroadcastChannel notification. |
| Closing Restore while asynchronous file validation was pending could update the wrong/closed dialog. | Validation callbacks must still own the same open form and selected-file ticket. | Delay validation, press Escape, allow response to arrive: no exception. |
| A rehashed analysis backup with empty histogram bins or malformed model results could pass validation and crash the renderer. | Linked analysis validation checks identities, dates, selected return basis, finite values, series lengths, scored origins/labels, models/horizons, intervals, simulation paths/bands and histogram totals. Exports validate linked analyses and enforce the matching 50 MB restore limit. Unknown backup wrappers reject explicitly. | Corrupted/rehashed backup tests, full isolated restore, all 12 previously completed test analyses remain compatible. |
| A forged cache fingerprint could return a different ticker's result. | Cache candidates must have valid complete analysis data and matching normalized configuration/code hashes. An existing request ID remains idempotent across code changes when its configuration matches. | Forged-fingerprint and existing-ID regression tests. |
| A rejected Quant request opened a result tab that only showed an unhelpful not-found screen. | The tab explains the actual request rejection, retains it across reload and offers an explicit retry in a distinct new tab. A saved server job always takes precedence over the local request notice. | Controlled queue-full response, reload, retry and persisted terminal job. |
| Starting a second server could open the same database and requeue work before failing on its occupied port. | The server reserves its loopback listener before opening SQLite or jobs. Invalid ports fail explicitly. A duplicate invocation leaves the running session unchanged. | Live duplicate-server test exits with the occupied-port explanation; original session token unchanged. |
| The archive materialized full datasets/results for up to 200 rows before returning small summaries. Variance and some portfolio lookups repeated unnecessary scans. | SQL returns only archive summary fields; variance computes its mean once; ledger/valuation membership and eligible quote lookups use sets/maps. | Summary-shape tests; exact variance arithmetic preserved; 100 deterministic independent ledger cases. |
| Extreme numeric histories could overflow and fail later with an undefined histogram/renderer error. | Non-finite returns/estimates and overflow/underflow scenario prices reject with a numerical-range explanation. | Extreme-history regression; independent results unchanged for the actual AAPL dataset. |
| Empty review-history IDs were accepted. | Review IDs must be nonempty and unique under the existing validation rules. | Core record-validation suite. |
| Activating the skip link changed the app route to `#main` and lost the active Quant screen. | The link focuses and scrolls to the main workspace without changing the active route. | Focus link, press Enter: `#quant`, form and main focus all retained. |

No schemas or model families were added. The variance optimization produces exactly the same arithmetic; the statistical model version remains unchanged. Implementation hashes still distinguish new computations/cache entries, and prior immutable runs remain retained.

## Independent accounting example and complete workflow

2. Buy 10 AAPL at supplied price 50, purchase fee 5: recorded cost 505 and cash 695.
3. Receive tagged dividend 12; withdraw 100: cash 607.
4. Sell 4 at supplied price 60, sale fee 3: proceeds 237; cash **844**. Release cost `505 × 4/10 = 202`; realized trading profit **35**; 6 shares retain cost **303**. Total fees **8**, dividend income **12**, external net contributions **100**.
5. Supply valuation price 70 USD: holdings value **420**, unrealized profit **117**, total with cash **1,264**. Recorded cost remains distinct from market value.
6. Reject sale of 7 remaining shares and a 10,000 withdrawal without changing records.
7. Link a real catalogue report to a TEST ONLY thesis; link a decision to that thesis/portfolio, record review dates and two append-only outcome reviews. Original rationale and expectation remain unchanged.
8. Acquire/retain a real AAPL Quant analysis, link its immutable ID/hash to both research records, reload and recover the same result.
9. Explicitly confirm a source-labelled Markets observation as a second valuation without replacing the user-supplied 70 USD record. Consequently the current preview's value differs from the original independent 1,264 example; its price history explains why.
10. Explicitly migrate that test browser workspace to its test vault, retaining the original browser key and recovery copy; reload, export complete linked analyses and restore to another fresh test workspace. Every private record and immutable reference matches the export exactly, and the restored analysis opens.

Automated cases additionally cover missing/outdated/incompatible prices, unknown cash versus zero, no cross-currency aggregation, fractional arithmetic, historical prices/events, overselling and negative cash. ## Remaining practical limits

- Public provider availability, rate limits, licensing and real-time entitlement remain outside this app's control. Successful reads today do not guarantee future availability. Errors stay explicit; missing observations are not invented prices.
- IDX Quant still needs at least 350 eligible completed observations and a known selected adjustment basis; the current owner-local BBCA history remains below that minimum. Markets daily-close browsing works separately.
- Bonds are bond ETF observations, commodities are futures quotes, and macro currently provides indices and official reference links; a numerical economic indicator feed is not connected. Their units/source types remain explicit.
- No FX conversion, broker sync, tax lots, short selling or automatic corporate-action changes to recorded trades. Unknown cash/missing/stale prices prevent complete totals/concentration. TWR/MWR still require a documented policy and full boundary valuations.
- Quant forecasts are retrospective studies and seeded scenarios are assumed-process simulations, not validated outcome probabilities or investment recommendations. Provider-adjusted history is acquisition-vintage data, not a point-in-time historical archive.
- Backups over 50 MB now fail clearly rather than producing a file the restore endpoint cannot accept. There is no backup pruning or split-bundle import yet. Preserve database copies and individual analysis exports when needed.
- Failed-submission notices store only their request configuration/error in local browser storage to survive reload; there is no dedicated cleanup screen for those notices yet.
- Clearing browser data can remove records or vault markers. SQLite is local but not application-encrypted. The loopback token is a local write defense, not authentication for hosting.
- Browser coverage uses Chromium with responsive viewports/touch context. Safari, Firefox, real-device keyboards and full assistive-technology certification were not performed.

The tested flows have no known remaining verified defect from this audit. Future provider/schema changes, unseen legacy data and untested environments can still expose issues; this report deliberately does not promise absolute zero bugs.
