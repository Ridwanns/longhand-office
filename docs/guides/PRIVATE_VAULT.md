# Private checkpoint service

GitHub Pages hosts only the frontend. Cross-device checkpoint sync requires this separately operated service on a private HTTPS host. No service has been provisioned by this change. Encrypted file transfer works without a server through Records → password-protected workspace backup.

The supplied service binds to loopback. Set `LONGHAND_VAULT_DB` to an absolute private database path outside the repository, public web directory, and Pages output. Set `LONGHAND_VAULT_ORIGINS` to a comma-separated, exact frontend origin allowlist, for example `https://ridwanns.github.io`. Run `node scripts/private-vault-server.mjs --init-vault` once to provision a vault. It prints an ID and a 256-bit bearer token: store these privately and do not commit them. Start `node scripts/private-vault-server.mjs`. Default port: 4176 (`LONGHAND_VAULT_PORT` overrides it). For local browser testing allow `http://127.0.0.1:4175` and connect to `http://127.0.0.1:4176`.

For other devices, an operator must supply an HTTPS reverse proxy, restrict network access, maintain Node/security updates, protect the host and credentials, configure request limits/timeouts, and back up the database using SQLite's consistent backup procedure. Preserve WAL files when applicable; copying just a live database file is not a verified backup. Test recovery on a separate instance. This implementation is a checkpoint service, not a complete identity, account recovery, or organization authorization platform.

In Records, connect with the service origin, vault ID and access token. The browser uses PBKDF2-SHA256 (600,000 iterations) and AES-256-GCM to encrypt a validated complete backup before upload. Passphrases and connection tokens are not persisted by the form. The server stores ciphertext, revision/request identifiers, content hashes and server receipt dates; it cannot independently certify forecast registration times or decrypt the backup. The active browser/SQLite workspace remains unencrypted.

Each checkpoint is immutable. A save requires the revision the client inspected; stale revisions receive HTTP 409. Repeating the same request ID and ciphertext is idempotent. Capacity is bounded (1 GB / 1,000 checkpoints by default), and a full vault rejects writes rather than deleting history. Refresh history after inspecting another device's changes. There is no automatic ledger merge, background sync, real-time collaboration or password reset. Restore validates/recomputes the backup and opens a new isolated workspace.

The frontend CSP permits user-configured HTTPS connections so a private host can be selected. The client rejects HTTP except loopback, URL credentials/query/fragments, and redirects; tokens are sent only to the explicitly connected service. A malicious or compromised frontend/host can still capture secrets. This is not a substitute for an independent security assessment.
