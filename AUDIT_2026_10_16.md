# Retained research and asynchronous interaction audit

16 October 2026 · Office local edition and rebuilt static browser edition.

## Reproduced defects

1. **A slow saved valuation or ticker could replace a newer choice.** Holding a real IndexedDB read, opening an AAPL archive entry, then typing MSFT reproduced AAPL appearing over the later selection. The valuation's old export could become enabled again. This was a selection-timing defect; ordinary reopened-valuation arithmetic already used the correct saved issuer and assumptions and was left intact.
2. **A delayed advanced archive could reveal old models after input changed.** Releasing the older AAPL model read after typing MSFT made the old results visible again. Opening a retained advanced study independently of the core run remains intentional and is explicitly labelled; allowing an obsolete action to replace a later interaction was the defect.
3. **An obsolete archive failure could replace current status.** A delayed read failure for the previous valuation replaced the new ticker's instruction/status even though that newer ticker was still selected. Error callbacks now follow the same context checks as successful reads.
4. **Leaving Quant during a manual archive read could throw.** A paused saved-calculation read, same-page navigation to Portfolios, and subsequent release reproduced `Cannot set properties of null (setting 'textContent')`. The original read was outside the handler's error boundary, and the catch path assumed the manual archive still existed.
5. **A completed ticker/valuation import could select its old result over later input.** The same missing context check applied after file parsing, validation and additive restoration. Regression scenarios now hold file reading, enter a new ticker, finish the import, and verify both successful archive persistence and unchanged newer UI selection.

## Changes

`research-intent.js` provides one shared guard for asynchronous archive actions. It captures the current form/view, location and interaction revision. A later input, selection, click or navigation invalidates an older pending UI action. The guard is applied to saved valuation, ticker and advanced opens, valuation/ticker restoration callbacks, and manual calculation opens. Successful older work cannot repaint the new choice, unhide old models or replace current status with a stale error.

Intentional imports still validate and add records. If the user changes view or ticker while importing, persistence can finish, but its old callback does not select the imported study. Returning to the archive shows the saved import. An older file operation only clears its own file selection; it does not erase a newer selected file. Normal archive opens still retain their exact original source values, settings and results.

Manual archive lookup and draft-readiness waits are now inside a guarded error boundary. The handler checks that its original view is still active before applying an artifact. An active read error is explained in the archive; a callback for a departed view does not address missing DOM elements or force navigation back.

No formula, market provider, source definition, portfolio ledger, saved-record schema, research link or model-result hash was migrated. The existing architectural appearance, Simple/Advanced navigation and Paper/Real separation are retained.

## Limits

This audit tests concrete reproducible interaction failures. It is not proof that every possible bug is absent. Market snapshots remain dated, some instruments lack enough eligible history, and provider outages can still withhold data. Active-record encryption and cross-device synchronization remain outside this release. Password-encrypted backup downloads and the established separate-workspace restore policy are unchanged.
